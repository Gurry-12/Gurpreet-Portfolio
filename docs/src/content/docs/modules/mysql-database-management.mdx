## 1. Module Purpose

Design normalized relational schemas, write high-performance SQL queries, index effectively, and connect Java to databases safely via JDBC.

---

## 2. Why It Matters for Software Engineering

Databases outlive applications. Poor schema design or inefficient queries cause 90% of backend scalability bottlenecks.

---

## 3. Learning Objectives

By completing this module, you will be able to:

- Design 3NF normalized relational schemas with appropriate constraints and data types.
- Write complex JOINs, subqueries, window functions, and transactions (ACID).
- Use JDBC `PreparedStatement` and connection pooling (`HikariCP`) to prevent SQL injection.

## 12. Common Mistakes & Anti-Patterns

Avoid these common database design and query traps:

- ⚠️ **Non-SARGable Queries & Function Wrapping**: Writing `WHERE YEAR(created_at) = 2026` suppresses the B+ Tree index, forcing an expensive `O(N)` full table scan. Use range comparisons: `WHERE created_at >= '2026-01-01' AND created_at < '2027-01-01'`.
- ⚠️ **Leading Wildcards in LIKE Queries**: `WHERE name LIKE '%smith'` cannot utilize B+ Tree prefix ordering, resulting in a full table scan.
- ⚠️ **Implicit Type Conversion**: Querying a `VARCHAR` column with an integer (`WHERE phone = 1234567890`) forces MySQL to cast every row, bypassing indexes.
- ⚠️ **Over-Indexing High-Throughput Write Tables**: Every index adds synchronous I/O page split overhead to `INSERT`, `UPDATE`, and `DELETE` operations.

## 13. Interview Relevance

Expect the following database engineering interview topics:

- 💡 **B+ Tree Architecture**: Why do databases use B+ Trees instead of Binary Search Trees or Hash Tables? How does high fan-out minimize disk I/O?
- 💡 **Clustered vs Secondary Indexes**: What is a bookmark lookup / secondary probe? How does a Covering Index eliminate it?
- 💡 **Isolation Levels & Anomalies**: Differentiate between Dirty Read, Non-Repeatable Read, and Phantom Read. How does InnoDB MVCC resolve them without read locks?
