## 1. Module Purpose

Containerize full-stack applications with Docker, multi-stage Dockerfiles, Docker Compose orchestration, and volume/network management.

---

## 2. Why It Matters for Software Engineering

Containerization eliminates the 'it works on my machine' syndrome and serves as the universal runtime unit for modern cloud deployments.

---

## 3. Learning Objectives

By completing this module, you will be able to:

- Write lightweight, multi-stage Dockerfiles for Java and Node.js applications.
- Orchestrate multi-container environments (Frontend + Backend + DB) using Docker Compose.
- Manage persistent storage with volumes and secure inter-container networking.

## 12. Common Mistakes & Anti-Patterns

Avoid these containerization anti-patterns:

- ⚠️ **Running Containers as Root**: Containers running as UID 0 that suffer an escape vulnerability give attackers instant root access to the host kernel. Always declare an unprivileged `USER nonroot`.
- ⚠️ **Bloated Single-Stage Docker Images**: Shipping build tools (Maven, JDK, npm, gcc) in production images increases image size by gigabytes and dramatically expands the CVE attack surface. Always use **Multi-Stage Builds**.
- ⚠️ **Hardcoding Secrets in Image Layers / ENV**: Environment variables baked into image layers persist in image history (`docker history`) even if overwritten in subsequent layers.
- ⚠️ **Storing State in Container Writable Layer**: Writing persistent data to the container filesystem rather than Docker Volumes causes data loss when the container restarts and incurs copy-on-write (CoW) performance penalties.

## 13. Interview Relevance

Expect the following DevOps and container architecture questions:

- 💡 **Container vs Virtual Machine**: Explain how Linux Namespaces (isolation) and Control Groups (resource quotas) create process boundaries on a shared host kernel.
- 💡 **Overlay2 Storage Driver**: How does the Copy-on-Write (CoW) union filesystem handle file modifications across image layers?
- 💡 **Layer Caching Optimization**: Why should `COPY package.json` precede `COPY .` in a Dockerfile?
